# MM2 toolkit v0.1.2 — log-dirs without `--json`

Date: 2026-09-10 01:44

Previous plan: `plans/2026-08-24_113700_mm2-prod-dr-storage.md`

## Goal

Make `compare_storage.sh` print per-broker GiB and extra-topic bytes on the live MM host
(`afr-dt-kmm-eb1`, Kafka CLI 3.9), after `kafka-log-dirs.sh --json` failed with
`json is not a recognized option`.

## Decisions

- Kafka 3.9 `LogDirsCommand` has no `--json`. Default output is JSON (plus
  `Querying brokers...` lines). Do not pass `--json`.
- Parse both partition maps (`{"topic-0": {size}}`) and KIP-849 arrays
  (`[{partition: "topic-0", size}]`). If JSON yields no rows, parse text.
- MM2 group `cg-charisma-genasia2afra-mirrormaker2` may be absent on source; describe
  on dest too and match names (`mm2|mirror|genasia`).
- `kafka-configs --all` can be missing the same way; retry without `--all`.

## Live findings that stay valid without sizes

- Identity policy `asia-gen -> afra-gen`; 14 dest-ahead topics (source retention).
- ~289 dest-behind topics (HWM lag). Do not treat `__consumer_offsets` as lag.
- Heap 2G is tight; Jolokia/REST absent on dedicated MM2.

## Verify on MM host

```bash
cd kafka_mirrormaker
./compare_storage.sh -c config/clusters/prod.env -c config/clusters/dr.env -y --via kafka
# expect: source/dest broker rows with cluster_GiB, not 0 / "-"
```
