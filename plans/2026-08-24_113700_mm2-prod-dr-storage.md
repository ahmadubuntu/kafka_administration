# Prod vs DR disk + MirrorMaker 2 checks

Date: 2026-08-24 11:37

## Goal

From the MM2 machine (`connect-mirror-maker.sh` + `/var/opt/kafka/config/mm2.properties`), using Kafka protocol + local CLI (SSH to brokers optional later), produce:

1. A storage/replication inventory that explains per-broker disk (193 GiB vs 280 GiB).
2. A separate MM2 health script (systemd, config, internal topics, lag, JMX if present).

New toolkit: `kafka_mirrormaker/` (same pattern as `kafka_topic_admin/`: reuse `kafka_realtime_check/lib`; no SSH by default).

## Decisions already made

- MM2 dedicated (`ExecStart=/var/opt/kafka/bin/connect-mirror-maker.sh /var/opt/kafka/config/mm2.properties`), systemd unit `mirrormaker2`.
- Runner has Kafka protocol to both clusters and Kafka CLI on the MM host; collection methods are pluggable (`--via kafka` now; `--via ssh` later).
- Do not merge into `kafka_topic_admin/compare_clusters.sh`.

## Scripts

- `compare_storage.sh` — probes: summary, logdirs, topics, configs, gaps, offsets
- `check_mirrormaker.sh` — probes: unit, config, process, internal_topics, lag, jmx, rest

## Out of scope

- Changing MM2 config or deleting dest topics.
- Implementing `--via ssh` fully in v0.1 (stub + skip message only).
